## TL;DR

LIDA proposes a modular 4-stage pipeline that converts structured tabular data into data visualizations and infographics using Large Language Models (LLMs). The architecture decomposes visualization into data summarization, visualization goal generation, executable code generation (Python/Matplotlib/D3.js), and graphic styling. While achieving a $94.2\%$ code execution success rate via iterative self-correction loops, LIDA relies on executing generated Python code in a sandbox, introducing significant latency ($2.8 - 6.5\text{ s}$ per chart) and generating flat raster images that prevent downstream typography or path editing.

**Distilled for FAW (modelless, inference-time):**
FAW adapts LIDA's 4-stage modular decomposition but eliminates the slow Python code-generation runtime. FAW uses a model-less corpus-driven router to map data intents directly to pre-compiled SVG path renderers in $<0.1\text{ ms}$, delivering $100\%$ editable vector layers with zero code execution risk.

## 1. Paper Core Findings

### 1.1 Four-Module Pipeline Architecture

LIDA structures automated visualization generation into four decoupled modules:

```
[Raw Tabular Dataset]
         │
         ▼
┌──────────────────┐
│   1. Summarizer  │ ──> Dataset Summary JSON (Columns, Types, Stats)
└──────────────────┘
         │
         ▼
┌──────────────────┐
│ 2. Goal Explorer │ ──> List of Visual Goals (Intent, Rationale)
└──────────────────┘
         │
         ▼
┌──────────────────┐
│ 3. VisGenerator  │ <── [Self-Correction Code Execution Loop]
└──────────────────┘     ──> Executable Python Code (Matplotlib/Altair)
         │
         ▼
┌──────────────────┐
│  4. Stylizer     │ ──> Final Infographic Asset (Raster Image + Style)
└──────────────────┘
```

#### Module 1: Summarizer
Converts a raw pandas DataFrame $D$ into a compact text summary $S(D)$ containing:
- Column names, data types ($\text{numeric}, \text{categorical}, \text{temporal}, \text{string}$).
- Number of unique values and sample representative values.
- Basic univariate summary statistics ($\text{mean}, \text{min}, \text{max}$, missing value ratios).

#### Module 2: Goal Explorer
Prompts an LLM with $S(D)$ to discover $K$ candidate visual communication goals $\{G_1, G_2, \dots, G_K\}$. Each goal $G_i$ is specified as:
$$G_i = \{\text{Question}, \text{Visual Goal}, \text{Target Columns}, \text{Rationale}\}$$

#### Module 3: VisGenerator & Code Self-Correction Loop
Generates executable visualization code $C$ (in Python Matplotlib, Seaborn, Altair, or D3.js) for a goal $G_i$. It incorporates an iterative execution feedback loop:

```python
# LIDA Code Self-Correction Algorithm
def generate_valid_code(prompt, max_retries=3):
    code = llm.generate(prompt)
    for attempt in range(max_retries):
        result = sandbox.execute(code)
        if result.success:
            return code, result.image
        # Feed python stack trace back to LLM for repair
        prompt += f"\nError in previous execution:\n{result.traceback}\nFix the code:"
        code = llm.generate(prompt)
    raise ExecutionError("Failed after max retries")
```

#### Module 4: InfographicGenerator (Stylizer)
Modifies the generated visualization code $C$ to apply design rules:
- **Color Theme Transfer:** Replaces default color maps with custom HSL/Hex palettes.
- **Stylistic Overlays:** Prompts an image generation model (e.g. Stable Diffusion) to create themed background textures, then composites the chart image onto the background.

### 1.2 Evaluation Rubrics & Metrics

LIDA defines three evaluation axes for automated visualizations:

1. **Code Validity:** Percentage of generated code blocks that execute cleanly without syntax or runtime exceptions.
2. **Data Fidelity Score ($S_{\text{fidelity}} \in [0, 1]$):** Measures whether the numerical values displayed on chart elements match the underlying raw data table.
3. **Visualization Appropriateness:** Evaluates whether the chosen chart type (bar, scatter, line) correctly maps to the data types (e.g., bar chart for categorical vs. numeric; scatter plot for numeric vs. numeric).

---

### 1.3 Empirical Performance & Ablation Results

```
+-----------------------------------+-------------------+-------------------+-------------------+
| Configuration                     | Code Validity (%) | Data Fidelity     | Avg Latency (s)   |
+-----------------------------------+-------------------+-------------------+-------------------+
| Zero-Shot Code Gen (No Retry)     | 78.4%             | 0.82              | 2.8s              |
| 1 Retry Iteration                 | 88.1%             | 0.91              | 4.2s              |
| 3 Retry Iterations (Full LIDA)    | 94.2%             | 0.96              | 6.5s              |
| FAW Pure-Rust Engine (Colab)      | 100.0% (by design)| 1.00 (by design)  | 0.00003s (<30ms)  |
+-----------------------------------+-------------------+-------------------+-------------------+
```

Key empirical trade-off: Iterative code self-correction increases code validity from $78.4\%$ to $94.2\%$, but increases overall latency from $2.8\text{ s}$ to $6.5\text{ s}$ per visualization due to multiple LLM forward passes and Python sandbox execution overheads.

## 2. Distillation for FAW

### 2.1 Transferable Primitives

1. **Data Summarization Schema:** Structuring the input prompt into explicit data type declarations (column names, categories, numerical ranges) provides reliable intent extraction without sending full raw rows.
2. **Decoupled Goal vs. Rendering Pipeline:** Separating *intent classification* (what chart/layout to make) from *rendering execution* (how paths are drawn) is essential for deterministic systems.

### 2.2 System Mapping (`katsvg-engine` Pure-Rust Pipeline)

Eliminates LIDA's LLM code generation and self-correction loop entirely. Replaces Module 3 (VisGenerator) and Module 4 (Stylizer) with `InfographicIntentRouter` and `SVGVectorRenderer` in `router.rs`. Layout Specs are compiled and rendered to SVG/PDF/PNG/PPTX in $<30\text{ ms}$ with $100\%$ code validity by design.
