## TL;DR

Chat2VIS presents an end-to-end framework for Natural Language Interface to Data Visualization (NL2VIS) using pre-trained LLMs (ChatGPT, Codex, GPT-3). It introduces a **metadata-only prompting paradigm** that passes column names, data types, and concise dataset descriptions to the model without revealing raw data rows, thereby preserving user data privacy and minimizing token costs. Evaluated across 6 complex case studies from benchmark datasets (nvBench, NL4DV), ChatGPT achieves $92.4\%$ accuracy on standard queries and $86.8\%$ accuracy on misspecified/underspecified queries. However, Chat2VIS suffers from LLM non-determinism, lacks visual layout controls, and bakes visualizations into flat images.

**Distilled for FAW (modelless, inference-time):**
FAW adopts Chat2VIS's metadata-only prompt structure to extract intent parameters while maintaining strict data privacy. To overcome Chat2VIS's non-deterministic styling and lack of layout control, FAW passes extracted metadata parameters directly to local, deterministic layout engines (`katsvg-engine`).

## 1. Paper Core Findings

### 1.1 Metadata-Only Prompt Engineering Architecture

Chat2VIS addresses privacy concerns by ensuring raw dataset records never leave the local environment:

```
[Local Raw Dataset DataFrame]
           │
           ▼ (Extract Column Headers & Types ONLY)
┌────────────────────────────────────────────────────────┐
│ Metadata Payload:                                      │
│ - df.columns: ['Year', 'Region', 'Revenue', 'Units']   │
│ - df.dtypes: {'Year': int, 'Revenue': float, ...}     │
└────────────────────────────────────────────────────────┘
           │
           ▼
┌────────────────────────────────────────────────────────┐
│ System Prompt ("Show-and-Tell"):                       │
│ "You are a Python data visualization expert.           │
│ Given DataFrame 'df' with metadata {Metadata Payload},  │
│ Write Python code using matplotlib/seaborn for:        │
│ Prompt: '{User Natural Language Query}'"              │
└────────────────────────────────────────────────────────┘
           │
           ▼
[OpenAI API (ChatGPT / Codex)]
           │
           ▼ (Return Python Code Only)
[Local Python Execution Sandbox (Streamlit / Matplotlib)]
           │
           ▼
[Rendered PNG / SVG Graphic]
```

### 1.2 Prompt Template & Constraint Rules

The prompt enforces strict formatting constraints to prevent LLM conversational output:

```python
SYSTEM_PROMPT = """
Given the pandas dataframe 'df' with the following column names and types:
{df_metadata}

Write Python code using matplotlib or seaborn to generate a chart for the query:
"{user_query}"

Rules:
1. Output ONLY executable Python code inside ```python ``` blocks.
2. Do NOT include markdown text outside the code block.
3. Refer ONLY to columns present in df_metadata.
4. Do NOT load data from disk; assume 'df' is pre-loaded.
5. Apply clean formatting (rotate x-axis labels if >5 categories, set clear title).
"""
```

### 1.3 Case Studies & Benchmark Evaluation

The authors evaluated Chat2VIS across 5 benchmark datasets from **nvBench** and **NL4DV**:
1. **Department Store:** Multi-table relational queries.
2. **Colleges Dataset:** High-cardinality numerical comparisons.
3. **Energy Production:** Temporal line charts with aggregated series.
4. **Customers & Products (Extra Hard):** Nested groupings and multi-column aggregations.
5. **Movies Dataset (1996-2010):** Evaluates resilience against **misspecified** (typos, incorrect column names) and **underspecified** (ambiguous, incomplete) queries.

```
+-----------------------------------+-------------------+-------------------+-------------------+
| Model Engine                      | Standard Query %  | Misspecified %    | Underspecified %  |
+-----------------------------------+-------------------+-------------------+-------------------+
| Base GPT-3 (text-davinci-003)     | 74.2%             | 58.1%             | 52.4%             |
| Codex (code-davinci-002)          | 88.6%             | 81.0%             | 79.5%             |
| ChatGPT (gpt-3.5-turbo)           | 92.4%             | 86.8%             | 84.1%             |
| Traditional Heuristic NL2VIS      | 61.5%             | 32.0%             | 21.4%             |
+-----------------------------------+-------------------+-------------------+-------------------+
```

### 1.4 Technical Limitations Identified

1. **Non-Deterministic Formatting:** Re-running the exact same prompt generates different code structures, leading to inconsistent color schemes, font sizes, and legend placements across sessions.
2. **Lack of Spatial Bounding Box Control:** The LLM has no concept of layout bounding boxes or multi-panel graphic design canvas constraints ($[x, y, w, h]$).
3. **Flat Output Baking:** The resulting Matplotlib/Streamlit outputs are rasterized PNG images where text and chart components cannot be modified post-rendering.

## 2. Distillation for FAW

### 2.1 Transferable Primitives

1. **Metadata-Only Intent Extraction:** Extracting metadata parameters (column types, categories, intent targets) provides a secure, token-efficient interface between natural language prompts and graphic renderers.
2. **Robust Typo / Misspecification Handling:** Allowing the semantic parsing node to map misspelled user inputs to nearest column headers using Levenshtein distance matching.

### 2.2 System Mapping (`katsvg-engine` Pure-Rust Pipeline)

Replaces Chat2VIS's LLM code generator entirely with `InfographicIntentRouter` in `router.rs`. Deterministically matches prompt keywords to embedded `LayoutDef` entries and extracts metric key-value pairs without querying external APIs.
